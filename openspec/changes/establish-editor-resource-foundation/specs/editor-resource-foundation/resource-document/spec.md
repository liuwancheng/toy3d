# Spec Delta

## Purpose

定义统一 Toy3d Asset 文件外层、类型化数据段、可靠读写与迁移规则，让编辑器能管理并保存模型、动画、碰撞和场景资源，而不要求这些资源具有相同的内部数据结构。

## ADDED Requirements

### Requirement: 通用 Asset 外层与类型数据分别建模
Toy3d Asset 文件 MUST使用统一的 magic、文件格式版本、Asset 身份、根类型身份、schema 版本、依赖/子资源索引和数据段目录；索引 MUST能在不解码全部类型数据的情况下读取。模型、动画、碰撞和场景 MUST能在相同外层内保存各自不同的类型化数据。显式声明且非 `Transient` 的创作属性 MUST由对应类型编解码器往返；本 change MUST同时交付序列化和反序列化。顶点/索引流、压缩动画曲线、碰撞加速结构等派生数据 MUST使用有界的独立数据段或外部 blob 引用，不能被强制展开为普通属性树。外部格式解析与转换 MUST由资源领域导入器负责，不得依赖属性用途标记触发。

#### Scenario: 大型模型数据
- **WHEN** 一个模型包含大量顶点和多个 mesh 子资源
- **THEN** Asset 文件 MUST能读取导入设置和子资源索引，而无需把全部顶点转换为属性树

#### Scenario: 外部模型与 Toy3d Asset 文件的职责边界
- **WHEN** 代表性模型资源记录外部源路径和导入设置
- **THEN** Toy3d 类型编解码 MUST能往返这些属性而不解析外部模型，属性用途标记 MUST不充当导入命令

#### Scenario: 未生成 Cook 产物
- **WHEN** 创作资源存在但目标平台的 Cook 产物缺失
- **THEN** Asset 文件 MUST仍可供编辑器打开；需要该产物的预览或运行时加载 MUST返回明确的未就绪错误

### Requirement: 格式与类型版本可独立演进
每份 Asset 文件 MUST记录文件格式版本及根类型的稳定身份和 schema 版本。文件格式与类型 schema MUST能分别迁移；读取旧版本 MUST按已登记迁移步骤转换并验证，未知不兼容版本 MUST失败。字段重命名或类型转换不得靠猜测名称或隐式数值截断。迁移失败 MUST保留原始文件和已加载的旧资源状态。

#### Scenario: 字段改名
- **WHEN** 旧碰撞资源使用 `half_extent` 而新 schema 使用 `half_extents`
- **THEN** 显式迁移 MUST得到新字段的等价值，并在再次保存时输出当前版本身份

#### Scenario: 未来版本
- **WHEN** 文件要求当前 reader 未知的文件格式或必需 schema 版本
- **THEN** 读取 MUST返回明确错误，不得以当前结构解释未知内容后覆盖原文件

### Requirement: 读写结果确定且失败不发布半成品
同一有效资源在相同版本下的逻辑序列化结果 MUST确定，不受无序容器迭代、模块注册顺序或宿主字节序影响。文件头、索引和数据段 MUST使用明确定义的字节序及有界编码，不得直接保存 C++ struct 内存布局；偏移越界、数据段重叠、大小超限和未知必需数据段 MUST被拒绝。解析和验证 MUST先形成完整的类型化候选结果，再替换调用方可见资源；错误 MUST携带资源身份、虚拟路径、属性路径或数据段身份及原因。数值溢出、非有限浮点、无效 UTF-8、数组/嵌套/总字节超限 MUST被拒绝。

#### Scenario: 数组中间元素无效
- **WHEN** 动画第 12 条轨道的第 8 个 key 时间为非有限值
- **THEN** 读取 MUST定位到该 key 并保持原资源不变

#### Scenario: 输出可复现
- **WHEN** 同一资源从不同注册顺序和无序容器插入顺序构建
- **THEN** 写入 MUST产生相同的规范化逻辑内容

### Requirement: 未知数据不能静默丢失
编辑器读取未知可选字段或可选数据段时，MUST保留足以重新保存而不丢失的数据，或把资源标记为不可修改/不可保存并返回原因；未知根类型也 MUST返回明确错误，不得用其他类型解码。它 MUST不在用户未察觉的情况下删除未知内容。运行时或 Cook 遇到未知必需字段、类型、数据段或引用时 MUST拒绝消费。

#### Scenario: 较新编辑器添加字段
- **WHEN** 较旧编辑器打开含未知可选属性或数据段的 Asset 文件
- **THEN** 它 MUST保留该属性完成无损往返，或拒绝保存并明确告知用户

### Requirement: 保存遵守文件系统 publication 边界
资源保存 MUST经共享 `FileSystem` 和 `VirtualPath` 执行完整候选写入，并检查写入、flush、close 与原子替换结果。发布失败 MUST保留旧文件可读，且不得把部分新内容视为已保存；跨多个文件的资源及派生产物 MUST有领域 publication 规则，不能假定单文件原子写入等于多文件事务。

#### Scenario: 写入中断
- **WHEN** 写入候选 Asset 文件时发生短写或替换失败
- **THEN** 保存 MUST返回失败，原资源文件 MUST继续可读，编辑器脏状态 MUST保留
